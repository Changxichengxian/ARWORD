词境前线｜内容维护说明

构建应用无需重新生成内容。以下用于未来扩充和修订。

源文件

tools/make_content.py 保存词汇、战斗阅读、听力、组句及来信原稿。
tools/visits.py 保存四次有限来访及其选择和结局。
生成结果是 app/src/main/assets/content.json、dictionary.db 和 tools/audio-manifest.json。
audio-manifest.json 保存每段录音的实际朗读文本。词义练习会读目标词及例句，来信和来访读正文。

Python 3 生成内容，保留随源码附带的词典：
  python tools/make_content.py --reuse-dictionary

需要重建词典时，从 ECDICT 项目自行取得完整 ecdict.csv，再传入：
  python tools/make_content.py --ecdict C:\path\to\ecdict.csv

词典以 ECDICT 的 BNC/FRQ 常用序号和本应用正文所需词形筛选，另有少数人工释义。源 CSV 不随源码包重复打包，所选数据库和 MIT 许可证已包含。只修改正文时，应运行内容核查，确认新增词形有释义；随附数据库不会凭空产生新词。
上游项目：https://github.com/skywind3000/ECDICT
许可证原文：https://github.com/skywind3000/ECDICT/blob/master/LICENSE

录音

录音使用 Windows 内置 Microsoft Zira Desktop 合成，并用 FFmpeg 编码为单声道、22,050 Hz、64 kbps MP3。工具需要 Windows PowerShell 5 的 System.Speech 和该语音。应用播放不需要这些生成工具。

  powershell -File tools/make_audio.ps1 -FfmpegPath C:\path\to\ffmpeg.exe

在 PowerShell 中只更新指定录音：
  .\tools\make_audio.ps1 -FfmpegPath C:\path\to\ffmpeg.exe -Ids 'l020','e00_0'

按编号前缀更新，如 e 开头的来访：
  .\tools\make_audio.ps1 -FfmpegPath C:\path\to\ffmpeg.exe -IdPrefix 'e'

正文、目标词发生变化必须重录对应文件。只改中文解释或选择题干扰项，不需要重录英文正文。先生成 content.json 和 audio-manifest.json，再更新录音。语音合成器的版本可能导致重新生成的音色或时长略有变化。

四段反馈音是 tools/make_sounds.py 生成的原创波形，不是外部游戏音效。

内容格式约定

skill：0 词义，1 阅读，2 听力，3 组句。
level：0–3 四档工作难度。它们是作者分组，未经过标准化测量校准。
kind：词义题按例句中的词性分组，生成同类中文干扰项；部分近义词在生成脚本中排除，避免两个译法同时成立。这个分组没有改变单词的其他词性，只针对该条例句。
signal：0 突击，1 固守，2 迂回，-1 与战术无直接映射。
id：固定唯一编号。个人存档引用编号；发布后不要随意把旧编号重新分配给另一条内容。
options/correct：选项与正确选项在原数组中的位置。界面会打乱显示顺序，存档仍保存原数组索引。
tokens：组句词块；全部应恰好覆盖目标句词块。alternatives 可添加合理的完整句变体；不支持自由文本语法分析。
story：12 封来信，每封短版紧接长版。界面按这个成对顺序读取，扩充时保持该约定。
event：来访没有标准答案；两项选择分别给 2 材料或 1 行粮。新增奖励类型要同时修改规则和界面，不能只改故事文本。

文字核查

  python tools/audit_content.py --ffmpeg C:\path\to\ffmpeg.exe

检查唯一编号、选项重复、答案范围、组句词块、词典数据库、正文词形以及全部音频的解码、时长和音量。输出在源码上一级的 qa/content-audit.json。
只检查文字与词典可加 --skip-audio；这不能代替音频核查。

机器核查不能判断每道题是否自然、干扰项是否合理、译文是否准确。新增材料仍需要人工复读。不要为了凑题量复制相同句子，也不要让中文选项直接把英文的信息全部提前说出。

当前材料是短期试验规模。扩充优先增加同一词在不同自然语境的再现、听力说话者与语速的多样性、真正需要理解关系的短文，而不是单纯增加更难的生词。
